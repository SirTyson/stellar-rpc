## Meta-Patterns

1. **Index-Driven Planner Obsoletes Range-Scan Hypotheses**: The `GetLedgerSequencesWithTransactions` + `BatchGetLedgersBySequences` index-driven architecture already solves overfetch more completely than any adaptive batch-sizing or streaming strategy. Any future hypothesis must verify whether its target code still exists.

2. **End-to-End Benchmark Dilution**: Multiple PoC-passing changes (FFI batching, context cancellation checks, tx-scoped streaming, oldest-ledger cache, envelope hash precomputation, diagnostic event dedup) showed no improvement or regression in full blaster sweeps. The 50/50 JSON/base64 mixed workload dilutes improvements targeting only one format path, and near-tip SQLite I/O typically dominates any serialization-layer saving.

3. **Decode Location ≠ Decode Cost**: Reorganizing WHERE decode happens (`BatchGetLedgers` vs `BatchGetLedgerMetas`, by-sequence streaming vs batch, handler vs DB layer) does not reduce total decode work. Only reducing HOW MANY decodes are performed (via better ledger selection) produces real savings.

4. **Fixed Per-Ledger I/O Swamps Variable Metadata Overhead**: String conversions, empty map allocations, lock scope on cache helpers, in-memory gap validation maps — all failed because the per-ledger SQL blob read + XDR deserialization (~100µs–10ms) is 3–6 orders of magnitude larger than any per-call metadata overhead being targeted.

5. **Cross-Subsystem Duplication at the Methods/DB Boundary**: The same `getTransactions` optimization can be framed from either the methods (caller) or db (data layer) perspective. Since most fixes require adding new query methods to `TransactionReader` or `LedgerReader`, investigating in the db subsystem first avoids redundant cross-subsystem failure.

6. **Partial Decode Is Intentional Design**: The `LedgerMetadataChunk` (raw bytes + header) pattern is deliberately chosen over `[]xdr.LedgerCloseMeta` to enable early validation before the expensive full decode, support sequential processing, and bound peak memory. Hypotheses that treat the partial-then-full decode sequence as a "double decode" misread the design intent.
